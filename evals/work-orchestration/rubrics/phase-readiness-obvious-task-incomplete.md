# Mandatory Phase Readiness For An Obvious Task

Pass only if the response says the phase is not ready for substantive editing
and applies the complete Phase Readiness requirements even though the
objective, target, owner, boundary, proof, and stop condition look obvious. It
must preserve the exact Phase Contract as the schema owner when serialization
or a downstream consumer needs it, but must not require loading that large
companion merely to repeat the complete eager fallback.

It must treat all five supplied gaps as readiness inputs:

- establish load-bearing mirror-write capability;
- obtain the current mandatory prerequisite result;
- bind the one paid run to explicit model, timeout, and stop constraints;
- record the material mirror-equivalence assumption with basis, impact, and a
  verification owner or point; and
- inspect the next contract checker's acceptance requirements.

The response may carry an unknown as an assumption or `Pending Verification`
only when it cannot change safety, target selection, acceptance, or proof. It
must not use that label as a blanket waiver for any supplied material gap. The
smallest next action is bounded readiness evidence collection without edits,
paid calls, external contact, or worker dispatch, followed by readiness
re-evaluation.

Fail if the response permits substantive editing first, treats readiness as
conditional on task complexity, uses only the abbreviated six-field subset,
ignores any supplied material input, mandates an unnecessary full companion
load, spends the paid call, or turns the explanation into implementation.

Call `set_waza_grade_pass` once if every requirement holds. Otherwise call
`set_waza_grade_fail` once and name the missing or contradicted requirement.
