# Scope Change Control Conditional Activation

Pass only if the response keeps case A with request-intake because the
ambiguity exists before a phase starts. It must activate
scope-change-control for case B, classify the generated consumer as a
material correctness expansion, absorb it only within the accepted
objective, permission, risk, and owner boundary, and otherwise split it
to the correct owner or stop. It must
activate scope-change-control for case C, classify it as
objective-changing, and hand it one-way to objective-lock without
bouncing the unchanged delta back. It must route case D to
task-suspension-checkpoint rather than hiding a tangent inside scope
control. It must say that ordinary implementation details already
implied by the accepted outcome do not activate the gate, optional
cleanup is deferred by default, and a known broad initiative remains
work-slicing's responsibility. It must not let scope control authorize
a broader write, publication, Production action, or objective change.

Call `set_waza_grade_pass` once if every requirement holds. Otherwise call
`set_waza_grade_fail` once and name the missing or contradicted requirement.
